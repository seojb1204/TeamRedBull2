# 아라쿠스 돌진 프레임 정렬 (main 기준)

기준: main `f13bb6b`. 브랜치 `fix/arakus-charge-frame-alignment-main`.
같은 수정을 PR #17(Charge 그림 1.25배) 위에 쌓은 버전이 PR #20이다. 두 PR은 같은 meta 줄을 다른 값으로 바꾸므로 **둘 중 하나만 병합한다**.

## 문제

철벽 돌진(`charge`) 중에는 `Charge` 2번·3번 프레임이 0.1초마다 번갈아 나온다.
두 프레임은 그림 안에서 몸이 그려진 위치가 서로 36px 다르다.
모든 프레임 피벗이 0.5라서 게임에서는 몸이 0.1초마다 약 0.9m씩 앞뒤로 튀고, 그림과 실제 판정 위치도 그만큼 어긋난다.
방패 투척 후 대쉬(`throw`)의 `ShieldThrowing_DashAttack` 2번·3번 프레임도 같은 문제로 26px(약 0.65m) 흔들린다.

## 변경

프레임마다 피벗 x를 골반 위치에 맞춰, 골반이 Idle 프레임과 같은 자리(피벗 오른쪽 2.3px)에 오게 했다.

| 스프라이트 | 피벗 x (px / 192) | 정렬 전 골반 | 정렬 후 골반 |
|---|---|---|---|
| Charge_00 (선딜) | 96 → 103 | +9.0px | +2.0px |
| Charge_01 (출발) | 96 → 118 | +24.7px | +2.7px |
| Charge_02 (달리기) | 96 → 85 | −8.8px | +2.2px |
| Charge_03 (달리기) | 96 → 121 | +27.1px | +2.1px |
| Charge_04 (정지) | 96 → 97 | +3.5px | +2.5px |
| ShieldThrowing_DashAttack_03 (달리기) | 96 → 122 | +28.6px | +2.6px |

- 달리기 루프 몸 흔들림: Charge 35.9px → 0.1px, ShieldThrowing_DashAttack 26.3px → 0.3px.
- 바꾼 것은 `.meta`의 프레임별 `pivot.x` 6개뿐이다. PNG 픽셀, 발 높이(pivot y), GUID, 슬라이스, PPU, 코드, 판정, 시간 값은 그대로다.
- ShieldThrowing_DashAttack의 나머지 프레임은 제자리 동작이고 차이가 6px 이하라 그대로 두었다.
- 피벗은 정수 픽셀로 맞춰 도트가 반 픽셀에 걸리지 않게 했다.
- 골반 위치: 붉은 깃털을 뺀 몸 픽셀 중 키의 55~75% 높이 띠의 평균 x.

`charge-alignment.gif`: 위는 main 그대로, 아래는 이 PR이다. 빨간 삼각형이 시뮬레이션상 실제 위치다.
게임 코드와 같은 타이밍(선딜 1.1초, 13m/s, 프레임 선택 규칙)으로 스프라이트를 다시 그린 것이고 **Unity 캡처가 아니다**.
`frame-overlay.png`: 달리기 프레임을 겹친 것이다. 왼쪽부터 Charge 정렬 전·후, ShieldThrowing_DashAttack 정렬 전·후.

## 검사

```sh
python3 Tests/verify-arakus-dash-alignment.py  # 피벗 값, 골반 정렬 ±1px, pivot x 외 meta 바이트 동일
```

- main의 원래 meta로 돌리면 실패한다(`Charge_00 pivot 96.0px, expected 103px`).

## PR #17과의 관계

- 이 PR이 먼저 병합되고 #17이 나중에 병합되면 Charge 그림이 1.25배로 바뀌어 피벗을 다시 계산해야 한다(105/124/83/127/98, PR #20의 값).
  이때 이 검사가 골반 정렬 실패로 알려 준다. #17의 `verify-arakus-charge-art.py`는 `Charge.png.meta`가 main과 바이트까지 같아야 하므로 그 검사도 함께 고쳐야 한다(#20에 고친 방식이 있다).
- #17이 먼저 병합되면 이 PR 대신 #20을 쓴다.

## 미검증

Unity 6000.4.0f1에서 이 브랜치의 재임포트, 실제 게임 화면, 좌우 반전 상태, 기둥 충돌 장면, Windows 빌드는 아직 실행하지 않았다.
같은 방식의 #20은 Unity에서 철벽 돌진 오른쪽 방향을 일시정지·프레임 진행으로 확인했다(몸이 일정한 간격으로 전진).
Unity에서 확인할 것: 철벽 돌진과 투척 후 대쉬를 좌우 양쪽으로 보고, 달릴 때와 선딜·출발·정지 자세로 바뀔 때 몸이 앞뒤로 튀지 않는지, 기둥에 박히는 위치가 그림과 맞는지.
