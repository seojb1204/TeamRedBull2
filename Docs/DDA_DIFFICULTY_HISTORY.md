# F8 DDA 배정 난이도 이력

## 브랜치와 변경 범위

사용자와 팀이 승인한 stacked 예외로 `feat/dda-difficulty-history`는
PR #14의 `feat/dda-debug-panel` 커밋
`fd9428f358dedc56a9c30ae02804c90585ebabc1`에서 분기했다.
PR #14는 PR #13의 DDA 보정을 포함한다. 부모 PR 병합 전에는 PR 대상을
`feat/dda-debug-panel`로 유지한다. 부모 PR 병합 이후에는 main과 중복 커밋,
파일 차이, 충돌을 다시 확인한 뒤 별도로 통합한다. 이 작업은 병합하지 않는다.

기존 공통 파일 변경은 승인된 `Assets/Scripts/DdaPanel.cs`의 패널 배치,
스크롤, 그래프 호출, F9 접기 입력뿐이다. 전투, 모델, 저장 진행도, CSV,
CloudSync, 씬, Prefab, 설정, 밸런스는 변경하지 않는다.

## 무엇을 측정하는가

표시명은 **배정된 공격 패턴 난이도 평균**이다. 체감 난이도나 UCB 점수가 아니다.
`SaveStore.BattleLogged`에서 완료 전투의 실제 `PatternStats.level`을 복사한다.
보스 정의의 패턴과 배정 결과를 ID로 검증하고 `AttackKind.Step`, `AttackKind.Rage`를
제외한 공격 패턴의 레벨을 같은 가중치로 평균 낸다. 실행하지 않은 공격도 포함한다.
누락/중복/범위 밖 배정은 임의 보정하지 않고 기록 오류로 표시한다.
공격이 없는 정의에는 평균을 만들지 않는다.

- 정상 승리와 사망: 보스별 완료 순번을 증가시키고 그래프에 기록한다.
- Fixed: 실제 배정값과 모드를 저장하며 회색 빈 점으로 구분한다. DDA 선과 연결하지 않는다.
- 포기/종료: 별도 감사 기록으로 남기되 완료 순번과 그래프에서는 제외한다.
- 진행 중: 현재 실제 배정값을 금색 빈 점으로 표시한다. 완료 선과 연결하지 않는다.
- 기존 사용자: 과거 전투의 배정값을 추정하거나 progress 이력에서 소급 생성하지 않는다.

## 파일과 데이터 흐름

1. `DdaHistoryRuntime`: F8 표시와 독립적으로 자동 시작하는 런타임 컴포넌트.
2. `DdaHistoryRecorder`: 기존 완료 이벤트 관찰, 보스 확인, 스냅샷 저장. 같은 결과 객체의
   중복 이벤트는 한 번만 처리한다. 자체 오류가 다른 이벤트 구독자로 전파되지 않게 한다.
3. `DdaDifficultyHistory`: 모델/스냅샷 검증, 평균, 복사, 그래프 구간/연결/변화량 계산.
4. `DdaDifficultyHistoryStore`: 별도 로컬 JSON 저장과 복구.
5. `DdaHistoryGraph`: 읽기 전용 그래프와 패널 화면 영역. 모델의 Prepare/Complete/Decide를 호출하지 않는다.

파일은 `SaveStore.Root/dda-difficulty-history.json`이다. 일반 실행에서는
`Application.persistentDataPath` 아래에 생성된다. 스키마 버전 1:

- `records`: GUID id, boss, recordedUtc(UTC ISO 8601), battle, dda, clear, abandoned,
  attackPatterns, average, patterns(id/kind/level).
- `counters`: 보스별 누적 완료 순번. 가지치기 후에도 순번은 계속 증가한다.

보스마다 최근 완료 200개와 포기 50개를 보관하고 그래프에는 최근 완료 20개를 표시한다.
임시 파일 기록 후 교체하며 `.bak`을 남긴다. 주 파일 손상 시 백업을 검사하고 경고를
표시한다. 복구 후 손상 원본은 `.corrupt.<GUID>`로 보존한다. 둘 다 손상되거나 미래 버전이면
읽기 전용으로 두고 덮어쓰지 않는다. 쓰기 실패 시 메모리의 Dirty 기록을 유지하고 5초마다
재시도한다. 디스크 실패 상태에서 프로세스를 강제 종료하면 미저장 기록은 유실될 수 있다.
이 파일은 CloudSync 업로드 대상에 추가하지 않는다.

## 조작과 표시

- F8: 기존 패널 열기/닫기. 기존 통계/다음 전투 예측/판단 이유/DB 상태를 유지한다.
- F9: 패널이 보일 때 그래프 접기/펼치기. 새 키이며 기존 전투 키는 변경하지 않는다.
- 휠과 스크롤바: 좁은 화면에서 패널 내용 스크롤. 전투는 계속 진행된다.
- Y축 -2~+2와 0 기준선, X축 실제 보스별 완료 순번을 사용한다.
- 연속된 DDA 완료 전투끼리만 선으로 연결한다. Fixed가 끼면 연결과 변화량을 끊는다.
- 0개는 기록 없음, 1개는 점만 표시한다. 최근 두 기록이 비교 가능한 경우에만 변화량을 표시한다.
- 점 위에 마우스를 두면 UTC 날짜/승패/평균을 표시한다. 클릭으로 접지 않으므로 공격/패링
  마우스 입력과 접기 기능이 겹치지 않는다.

## 자동 검사와 한계

Linux에서 .NET SDK 8.0.427을 이용해 다음을 실행했다.

```sh
python3 Tests/run-dda-history.py --dotnet /path/to/dotnet --suite history
python3 Tests/run-dda-history.py --dotnet /path/to/dotnet --suite logic
```

이력 검사 47개, 부모 브랜치의 기존 로직 검사 128개가 통과했다. 이력 검사는 평균,
비공격 제외, 실행하지 않은 배정, Fixed/포기/사망, 중복, 보스 분리, 복구, 실패 재시도,
보관 한도, 실제 완료 이벤트와 1~6판의 관찰 유무 비교를 포함한다. 마지막 비교에서는
배정 레벨과 A/b, 패턴 기억, 학습 카운터를 포함한 최종 learning JSON이 동일했다.
이 검사는 그래프 데이터 조회의 무변경성을 확인하며 실제 GUI 이벤트 전체를 재현하지 않는다.

실행기는 허용 목록의 소스와 UnityShim만 임시 디렉터리에서 실행하며 CloudSync와 실제
DB 설정을 포함하지 않는다. UnityShim의 JSON은 DataContractJsonSerializer이므로
Unity JsonUtility의 실제 직렬화와 동일하다고 보장하지 않는다.
변경 C# 6개는 Roslyn 문법 검사에서 오류 0개였다. 이는 Unity API 컴파일 검사가 아니다.
`Verify-DdaHistory.ps1`은 Windows/Unity 설치용 검사 진입점이며 이 Linux 환경에서는
실행하지 않았다. Unity Editor 실행, 화면 캡처, Windows 빌드는 아직 검증하지 않았다.
