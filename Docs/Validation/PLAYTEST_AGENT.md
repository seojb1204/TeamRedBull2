# DDA 안정성 + 자동 플레이 검증

## 무엇을 자동화했나
`-towerAgent novice|balanced|expert`는 게임 안에서 이동/공격/패링/회피/스킬/회복 **입력만** 만드는 규칙 기반 테스트 에이전트다. 체력·피해량·무적·판정·보스 기믹을 바꾸지 않는다. 컴퓨터 비전/LLM 플레이어나 인간 실력 모델은 아니다. 내부 패턴·선딜 시각을 관찰하는 **특권적 계측 에이전트**다. 프로필은 대응 확률/공격 빈도 차이이지 인간 초보/고수의 통계적 재현이 아니다.

`-towerBoss 0..4`, `-towerSeed 정수`를 지원한다. 일반 플레이는 명령행 인자가 없으면 그대로다. 보스 해금만 격리 저장에서 시험 편의상 열고 이를 보고서에 표시한다. 시드는 보스 RNG와 에이전트 RNG 각각에 주입하며, VFX 난수와 분리된다. Unity 실제 가변 프레임까지 bit-identical을 보장하지 않는다.

자동 실행 인자가 있으면 CloudSync는 설정 읽기·PlayerPrefs·전송 큐 생성 이전에 종료한다. 실제 실행 검증은 추가로 DB 설정 파일이 없는 **독립 사본**을 사용한다. 실제 프로젝트/사용자 저장을 대상으로 실행하지 않는다.

## 빠른 헤드리스 검증
```
python Tests/run-playtest-agent.py --dotnet <dotnet 경로> --output <새 CSV 경로>
python Tests/run-dda-robustness.py --dotnet <dotnet 경로>
```
240 전투(3프로필 × 2시드 × 5보스 × DDA ON/OFF × 4라운드)가 실제 `TowerGame.Update`/전투 소스를 실행한다. UnityShim으로 입력/렌더링을 대신하므로 **Unity 실행 검증이 아니다**. 120초 제한은 포기로 처리해 DDA 실패 학습에 넣지 않는다. 동일 시드 재실행의 결과 동일성, 수치 유한성, 난이도 범위, 저장 격리를 검증한다. CSV에 매전투/패턴별 난이도, 기회, 성공률, 피격, 보스 HP, 승패가 남는다.

## 실제 Unity 실행파일 검증
Unity 6000.4.0f1 독립 사본에서 빌드한 실행파일로:
```
python Tests/run-unity-playtest-agent.py --exe <game.exe> --output <새 결과 폴더> --boss 0 --profile balanced --seed 17 --rounds 3 --seconds 60
```
DDA OFF 비교는 `--no-dda`를 붙이고 별도 결과 폴더를 사용한다. 자동 새 temp 저장을 만들어 라운드 사이에만 재사용한다. 게임이 1회 끝나거나 시간 제한에 도달하면 종료하며 다음 프로세스를 실행한다. 리포트·로그·실행파일 해시를 보존한다. 실제 시간/실행 환경 때문에 시드가 같아도 입력 프레임이 달라질 수 있다.

## 결과 해석과 한계
- 최초 헤드리스 240전투: expert 13/40승(DDA) vs 12/40(OFF), balanced 8 vs7, novice1 vs3. 이 작은 표본은 **DDA가 승률/재미를 개선했다는 증거가 아니다**.
- 실제 플레이 기회는 5666개, 34개 보스/패턴 조합 관찰. 성공률 주입 시뮬레이션과 달리 입력이 실제 전투/판정 결과를 만든다.
- 같은 시드 ON/OFF는 기본 비교 기준일 뿐, 플레이 결과에 따라 난수 소비/패턴 경로가 달라질 수 있다.
- 멀리 피한 것도 성공률로 잡힐 수 있어 성공률 단독 최적화 금지. 승패, 보스 HP, 소요시간, 피격을 함께 본다.
- 현재 반응 정책은 모든 연속공격·투사체·안전지대 기믹을 능숙하게 풀지 않는다. 에이전트 실패가 곧 게임 결함은 아니다.
- 렌더링, 입력 지연, 좌우 반전, 체감 공정성과 재미, 사람의 60~80% 성공률 수렴은 별도 사람 플레이테스트가 필요하다.
- 기준 수치/보스 기믹은 유지하며, 손상된 학습 데이터·중복 완료·관측 없는 완료의 안전성만 강화한다.
