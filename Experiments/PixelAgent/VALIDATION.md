# 검증 기록 및 다음 단계 (2026-11-13)

## 구현 범위

- 기준 로컬 통합 트리: `21ccd15` (PR26 + PR27). 별도 `experiment/pixel-agent` 브랜치. 본편에 병합/배포하지 않음.
- Unity 최종 화면 RGB 160×90, 4 고정 프레임마다 행동 1개. 대기 중 게임 전투를 멈춘다.
- 정책 입력은 RGB와 직전 RGB 차이뿐. 내부 HP 변화/종료는 보상 채널에만 사용.
- Arakus만, DDA OFF, 포션/스킬 제외. 기존 PR26 봇처럼 내부 패턴 타이밍을 읽지 않는다.
- 보상: 보스 HP 감소 비율 − 플레이어 HP 감소 비율 − 결정당 0.001, 승리 +1 / 패배 −1.
- 60초 시뮬레이션 상한, 기본 180초 벽시계 상한, 15초 무응답 오류. 종료와 시간제한을 구분.
- 클라이언트 타임아웃은 오류로 기록하며, 같은 보상을 두 번 학습시키지 않는다.

## 실제 실행한 검사

- Python unittest 10개 통과: 픽셀 처리, 보상과 정책 분리, 체크포인트, 가짜 transport 왕복, stale ID, 오류 종료, 안전 실행 가드.
- 실제 `PixelAgentBridge.cs`를 .NET 8에서 API shim과 컴파일해 23개 검사 통과. 프레임 방향/형식, 4프레임 입력, 단발 버튼, stale action, 보상, 종료, 격리/DB/oracle/DDA 거부.
- 리뷰에서 발견한 `BossPatterns` 인스턴스 접근 오류 수정 후 재검사.
- synthetic: 3색 화면 행동 선택 과제, seed17/29/43. 학습 후 100%, 무작위 14.05~17.14%. **이 수치는 Arakus 승률/게임 실력이 아니다.**
- 기존 HEADLESS 로직 검사는 통과(132 assertions). 전체 회귀 스크립트의 9 suite 중 8 통과, 방 리소스 suite의 98항목 중 97통과. 실패 1건은 `HEAD` 대비 공통 코드가 변경되지 않아야 한다는 아트 전용 가드로, 본 실험이 의도적으로 `TowerGame.cs`/`AutoRun.cs`를 변경했기 때문. 검사를 삭제하거나 기준을 약화하지 않음.

## 아직 실행하지 않은 것

**실제 Unity API 컴파일, Windows 빌드, 실제 화면 캡처 왕복, Arakus 학습/평가 모두 미검증.**

사용자 PC에서는 기존 PR26 빌드/배포가 진행 중이라 이 실험의 프로세스를 시작하지 않았다. GPU를 사용하지 않았고 ML 패키지/모델도 설치하지 않았다. 최소 학습 코드는 복잡한 보스 전략을 배우기에 표현력이 부족할 수 있다. 사람같은 AI가 완성되었다고 해석하면 안 된다.

## 이어서 실행할 안전한 검증

1. 별도 프로젝트 복사본에 이 변경을 적용. 원본 게임/저장/설정은 그대로 둔다.
2. 복사할 때 `Assets/StreamingAssets/supabase.json`만 제외한다. 내용을 읽거나 출력하지 않는다. Art/Audio는 유지한다.
3. Unity6000.4.0f1로 컴파일/Windows Mono 빌드. 독립 빌드가 안전 마커를 포함하는지 runner가 확인한다.
4. random과 rule 각각 1회 짧게 실행, 실제 화면의 캡처와 조작을 눈으로 확인한다. 최초 테스트는 `--seconds 60 --episodes 1`.
5. 연결이 정상인 경우에만 짧은 학습 3회와 별도 평가 진행. 현재 실행기는 최대3회×180초로 제한하며 장시간 GPU 학습을 시작하지 않는다.
6. 실제 개선 여부는 훈련 seed와 분리한 평가, 같은 행동 집합/프레임 조건에서 판단한다. 초기 1~3회로 학습 성공을 주장하지 않는다.


## 실제 Windows 후속 검증

아래 내용은 위 초기 미실행 기록을 갱신한다. Unity6000.4.0f1 실제 컴파일·Windows Mono 빌드 및 내부 RunChecks 통과. RTX5080 renderer로 실제 게임 화면을 캡처해 직접 확인했다. 정책-입력 왕복과 종료가 정상 동작하며, 사용자 PC의 기존 프로젝트/저장/DB를 사용하지 않은 독립 사본에서 실행했다.

최초2회 테스트는 Windows 파일 공유 잠금 때문에 실패했다. numbered `transition_N.json` 프로토콜, bounded retry, watchdog으로 수정한 뒤 5전 정상 종료. 실패를 성공으로 세지 않는다.

훈련 누적1255회 업데이트 및 평가 중 체크포인트 불변을 확인했다. **학습 코드가 실제 화면/보상으로 갱신되지만, 이 짧은 실험에서는 전투 학습에 실패했다.** 학습 후 평가 보상은 random보다 낮고 공격하지 않는 퇴행이 관찰됐다. 승률 향상이나 사람같은 AI를 완성했다고 볼 수 없다. 정확한 수치와 행동 분포는 WINDOWS_RESULTS.json에 있다.

다음 개선은 더 오래 돌리기보다 시각 인식과 학습 구성을 바꾸는 것이다. 플레이 영상·행동 기록 기반 모방학습, 보다 풍부한 픽셀 표현(CNN), 정지/회피만 하는 보상 편법 점검, 훈련seed와 분리된 여러 평가전이 필요하다. 기존 작은 실험기는 그 비교를 위한 격리·관찰·행동·보고 기반으로 사용할 수 있다. 시뮬레이션은 관찰/행동 사이 멈추므로 인간의 실시간 반응 검증이 아니다.


## 두 번째 8전 제한 실험 결과

초기 정지 퇴행의 원인을 원본 픽셀 검출 실패와 배경 특징 중복으로 좁히고, Q표와 역순 replay로 교체했다. 원래 모델과 데이터는 보존했다. Unity 재빌드와 정책·평가 정보 분리 검사를 통과했다. Python 24개, C# shim 29개 검사를 GitHub fb0bcb3의 별도 사본에서 재실행해 통과했다.

훈련 seed 17/18/19/20의 4전에서 실제 전이 2,117개와 제한 replay 16,936회를 처리했다. 평가 seed 101/102는 훈련에 넣지 않았고 탐색률 0, 업데이트 없음, 체크포인트 불변을 확인했다. 총 8전 모두 패배했다. 아래 수치는 개선 방향을 보는 작은 표본이지 일반화나 승률 향상 증거가 아니다.

추가 결함: 매 행동 -0.001 벌점이 길게 싸우며 더 많은 피해를 준 시각 규칙보다 빨리 패배한 학습 정책에 더 높은 보상을 주었다. 따라서 보상 수치 상승만으로 성능 개선을 주장하지 않는다. ITERATION2_RESULTS.json의 낮은 벌점 가상 점수는 진단 계산이며, 그 보상으로 새 학습·평가한 결과가 아니다. 다음 수정은 벌점 설계, 시각 경고의 시작·증가량을 이용한 패링 타이밍, 공격 방향과 상대 방향 일치다.

시스템 전체 GPU 측정 76회: 사용률 0~4%, 평균 2.32%, 최대 49도, 메모리 최대 1,895 MiB, 전력 최대 57.58W였다. 다른 앱도 포함한 값이며 학습은 CPU 표 연산이다. 모든 8전 수치, 행동 분포, 검출 실패 비율과 체크포인트 검증은 ITERATION2_RESULTS.json에 있다. 이번 실험의 게임·Unity 프로세스는 종료했다.
